# SmartHomeOffline ESP32 firmware

`SmartHomeOffline.ino` is the supplied smart-home sketch with the assistant
integrated directly into it. GPIO, PCF8574, device, sensor, Firebase sync, HTTP,
and BLE behavior from the supplied firmware are retained.

This folder is the firmware to flash. It is one combined Arduino sketch; do not
flash the optional reusable module in `esp32_offline_assistant/` instead.

The assistant path itself is local-only:

1. Flutter recognizes speech with the phone's on-device recognizer, or the user
   types a command.
2. Flutter sends text over the LAN or the existing BLE characteristic.
3. This sketch matches English/Arabic device, room, and sensor intents locally.
4. The ESP32 switches the selected PCF8574 output immediately.
5. The response returns to Flutter; optional English speech is generated by
   ESP8266SAM on the ESP32.

Firmware `2.6.0-music-multidevice` keeps local control responsive by
deferring BLE callback work to `loop()`, sending Firebase state updates from a
low-priority worker, and applying a 30 ms I²C transaction timeout. Flash the
combined sketch and confirm this version string in Serial Monitor before
testing the updated Flutter application.

This build also matches every separately named device in one command. For
example, `turn off TV and Desk Lamp` changes only those two relays and returns
both names. `Turn off two devices` without names is intentionally rejected as
ambiguous. Phone-local music commands are handled inside Flutter and are not
sent to a relay or to this firmware.

There is no OpenAI client, API key, assistant server, remote-model call, remote
audio URL, or unknown-command network fallback in this sketch. The existing
Firebase code is only for registration and home-state synchronization.

## Hardware map retained from the supplied sketch

| Function | Default connection |
| --- | --- |
| DHT11 data | GPIO15 |
| Flame sensor | GPIO34, active-low alarm |
| I2S BCLK | GPIO26 |
| I2S LRC / WS | GPIO25 |
| I2S data to amplifier | GPIO27 |
| I2C bus 0 | SDA GPIO21, SCL GPIO22, enabled |
| I2C bus 1 | SDA GPIO4, SCL GPIO14, disabled by default |
| First PCF8574 | Bus 0, address `0x20`, active-low outputs |

I2C buses, PCF8574 addresses, and module/channel assignments can still be
changed through the existing app/API. Confirm the board wiring before applying
power; do not infer voltage limits from GPIO numbers alone.

## Arduino setup

1. Install Arduino IDE and the **esp32 by Espressif Systems** board package.
2. Install these libraries with **Library Manager**:
   - **ArduinoJson 6.x**
   - **NimBLE-Arduino**
   - **DHT sensor library by Adafruit**
   - **Adafruit Unified Sensor**
3. For optional local English speech, also install:
   - **ESP8266Audio**
   - **ESP8266SAM**
4. Open `SmartHomeOffline.ino` in Arduino IDE.
5. Select the exact ESP32 board and serial port. For a common development board,
   start with **ESP32 Dev Module**.
6. Click **Verify**, then **Upload**. Open Serial Monitor at **115200 baud**.

If the two speech libraries are absent, the sketch intentionally disables only
the ESP32 voice output at compile time. Local intent matching, phone speech,
BLE, HTTP, and relay control continue to work.

## First connection

- With no saved Wi-Fi credentials, connect a phone to `ESP32_Config` using the
  development password `12345678`, then complete the captive-portal setup.
- The serial monitor prints the controller's LAN IP after it joins Wi-Fi.
- Run Flutter with that address, for example:

```bash
flutter run --dart-define="ESP32_LOCAL_IP=192.168.1.50"
```

The IP is a controller address on the local network, not a backend URL.
Normally Flutter discovers this address from the controller registration or
BLE status. `ESP32_LOCAL_IP` is only an explicit development override.

## Customer assistant name

Flutter sends the selected name over local HTTP or BLE. This sketch validates
it and stores it in ESP32 Preferences/NVS under the `assistant` namespace, so it
survives a restart. It is never stored in Firebase.

Local API:

```text
GET  /api/assistant/name
POST /api/assistant/name   {"assistantName":"Noor"}
POST /api/ellie            {"text":"Noor, turn on the living room light","assistantName":"Noor","speak":true}
POST /api/ellie            {"text":"Noor, turn off TV and Desk Lamp","assistantName":"Noor","speak":false}
POST /api/ellie/speak      {"text":"The living room light is on."}
```

BLE uses the existing service and command characteristic:

```text
Service: 4fafc201-1fb5-459e-8fcc-c5c9c331914b
Command: d8e3b8a2-4f5c-4b6e-9a2f-1a2b3c4d5e6f
```

Name command:

```json
{"cmd":"set_assistant_name","assistantName":"Noor"}
```

Status command returned to Flutter:

```json
{"cmd":"status"}
```

The response includes `firmwareVersion`, `assistantReady`, `assistantName`,
`speakerEnabled`, controller `ip`, sensor values, and module/device counts.

## Important voice limit

This original ESP32 sketch has no microphone input or speech-recognition model.
It contains the local intent engine and optional speaker output. The Flutter app
provides offline English/Arabic speech-to-text and sends only recognized text.
For a controller that listens directly without a phone, use an ESP32-S3 plus an
I2S microphone and an ESP-SR fixed-command firmware variant.
